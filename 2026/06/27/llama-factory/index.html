llama-factory框架的组成部分

Model Loader

负责模型的加载、适配与优化，支持LLM和VLM两类模型。

  • Initialization：使用Transformers库中的AutoClasses，加载model和tokenizer
  • Patches：支持Flash attention等优化，提供GPTQ等量化微调
  • Adapters：使用PEFT库挂载lora等adapter，自动识别模型架构
  • Quantization：量化，对接 bitsandbytes，在加载时直接将模型量化为 4-bit（NF4）或 8-bit 状态，为 QLoRA 铺平道路。

Data Worker

负责将原始数据标准化并转化为张量（Tensor），包含 4 个步骤：

  • Loading ：从本地文件或 ModelScope/Hugging Face 动态加载原始数据集。
  • Aligning：数据对齐。根据 dataset_info.json 的配置，把不同的数据字段（如 instruction/input/output）映射到框架统一的内部数据结构中。
  • Preprocessing：预处理。核心是应用 Chat Template（对话模板）。将结构化数据拼接成带有模型特定 Special Tokens 的文本，进行 Tokenize，并实施 SFT Loss Mask（把 Prompt 部分的 Labels 设为 -100）。
  • Merging：数据合并与打包（Packing）。支持将多条短对话拼接（Pack）到设定的最大长度（如 4096），减少 Padding 带来的计算浪费。

SFT Loss Mask（监督指令微调损失掩码）

SFT Loss Mask 是让模型只对 Assistant 的回答（答案）计算 Loss，而忽略 User Prompt（提示词）的机制。将数据集中的指令（Prompt）部分的 Labels 设为 -100，只训练 Response 部分。

  • 为什么要 Mask？ 如果不进行 Mask，模型在训练时不仅要学会怎么回答问题，还要去预测和学习人类是怎么提问的（甚至去学习 System Prompt 这种固定套话）。这会导致模型在线上对话时，经常莫名其妙地复读用户的话，或者角色错乱。
  • 具体怎么实现？ * 在 PyTorch 里面，计算交叉熵损失（CrossEntropyLoss）时有一个标准参数 ignore_index，它的默认值通常是 -100。
    • Data Worker 在生成 labels 序列时，会把属于 System Prompt 和 User Input 对应的 Token ID 全部替换为 -100，只有属于 Assistant Output 的 Token ID 保持原样。
    • 在反向传播时，PyTorch 看到 -100 就会自动跳过，其梯度为 0。

Tokens: [<|im_start|>, user, \n, 你, 好, <|im_end|>, \n, <|im_start|>, assistant, \n, 我, 是, AI, <|im_end|>]
Labels: [ -100, -100, -100, -100, -100, -100, -100, -100, -100, -100, 我, 是, AI, <|im_end|>]

Packing

大模型微调时通常会设置一个最大长度（如 --cutoff_len 4096）。如果数据集中绝大多数对话都很短（比如只有 200 个 Token），传统的做法是在后面强行补 3896 个 Padding Token（如 ）来凑齐 4096。
尽管这 3896 个 Pad Token 在计算 Loss 时被 Mask 掉了，但它们依然要在 Transformer 里跑完整的前向和反向传播，造成了极其巨大的算力浪费。

Data Worker 的 Merging 操作采用了一种 “贪心拼接” 的策略：

  • 打碎边界： 它它把数据集中所有不同样本的多轮对话序列（已经转成 Token ID，且各自带有 EOS 结束符），看作一个连续的 Token 流。
  • 贪心填充： 不是用按照“一个样本占一行”的方式训练。而是像拼积木一样，把样本 A（长 500）、样本 B（长 1200）、样本 C（长 2000）连续拼接在同一行里，直到接近或刚好填满 4096 的最大长度。
  • 处理截断： 如果下一个样本放不下了，就把它截断，前半部分补在当前行末尾凑满 4096，后半部分放到下一行作为开头。
  • Attention Mask 隔离（关键）：
    • 把多个不相关的样本拼到一行，如果不做处理，模型在计算 Attention 时就会发生“记忆串串”，让样本 B 看到了样本 A 的内容。
    • 为了防止这种交叉污染，Data Worker 会重构 attention_mask（通常使用二维块状 Mask，即 Block-Diagonal Attention Mask） - 为了防止这种交叉污染，Data Worker 会重构 attention_mask（通常使用二维块状 Mask，即 Block-Diagonal Attention Mask），强制规定在同一个 4096 序列内，只有属于同一个样本的 Token 之间才能互相看到，不同样本之间不可见。

开启 packing: true 后，由于完全压榨了每一行 4096 长度的计算空间，训练吞吐量（Tokens/s）通常能提升 2x 到 4x 不等，极大缩短了训练时间。

处理截断可能会将一个样本分割成两半？
这样的操作对整体影响很小，原因如下：

  • 因果注意力的本质是通过上一个token预测下一个token，所以即使样本被分割成两半，上半部分和下半部分都是完整的，可以正常训练；
  • Block-Diagonal Attention Mask，通过强制mask保证样本之间不会相互影响
  • 相对位置编码（RoPE）保证两个部分的token位置编码是连续的，不会因为被截断而断开。

但是还是存在缺点的：从transfomer的角度来说，把样本变成两半，那么就会丢失用上半句的最后一个token预测下半句的第一个token的训练过程
为了完美解决这个问题，我在实际工程中通常会采取两种优化策略：

  • 调整 SFT Loss Mask：对于被截断到下一行开头的后半部分样本，对其前 KKK 个 Token 的 Loss 进行 Mask（置为 -100）不计入梯度。因为这些 Token 失去了关键的前半句上下文，强行让模型去预测它们会产生错误的梯度噪声。直到它们运行了几个 Token、重新建立了自回归上下文后，再开启 Loss 计算。
  • Best-Fit Packing（最佳适应打包）：在数据预处理阶段放弃贪心截断，改为求解装箱背包问题，让不同长度的样本通过组合恰好凑满窗口，如果凑不满宁可留有一点点 Padding 也绝不截断。

Trainer

Model Loader 吐出“组装好的模型”，Data Worker 吐出“处理好的数据”，两者在 Trainer 会师。Trainer 内部被清晰地解耦为两部分：

🔹 Optimization（优化技术）

支持多种前沿的低资源微调算子：

  • LoRA：传统的低秩自适应微调。
  • PiSSA：一种新型微调方法（Principal Singular Values and Singular Vectors Adaptation），利用主成分分析对原权重矩阵进行奇异值分解（SVD）来初始化 LoRA 的 A 和 B 矩阵，通常比普通 LoRA 收敛更快。
  • GaLore：梯度低秩投影。不改变模型权重，而是在梯度层面做低秩分解，大幅降低全量参数微调（Full Fine-Tuning）时的优化器状态显存占用。
  • BAdam：一种内存高效的块状 Adam 优化器（Block-wise Adam），每次只更新模型的一个子块，从而让单卡能跑更大模型的全量微调。

🔹 Approaches（训练范式）

支持大模型生命周期中的所有主流训练阶段：

  • Pre-train：增量预训练（Causal LM Loss）。
  • SFT：监督指令微调（Masked Cross-Entropy Loss）。
  • RLHF：传统的基于人类反馈的强化学习（包含 Reward Model 训练和 PPO 阶段）。
  • DPO：直接偏好对齐，以及图里没写但论文提及的 ORPO、KTO 等变体。

LlamaBoard

作为外围的系统级 Demonstrations 工具，通过双向箭头与 Trainer 交互：

  • Experiment Configurator：实验配置器。用户在 WebUI 上点选模型、数据集、学习率、微调方法（LoRA/PiSSA等），一键将超参数下发给 Trainer 启动训练。
  • Training Status Monitor：训练状态监控器。Trainer 在训练过程中实时的 Loss、Learning Rate、吞吐量（Tokens/s）等指标，反向喂给面板，在前端渲染出实时的折线图。

关键参数

参数名 典型值 作用与面试考点
--stage sft 训练阶段：pt (预训练), sft (指令微调), rm (奖励模型), ppo/dpo (对齐)。
--model_name_or_path meta-llama/Meta-Llama-3-8B 基座模型路径（本地或 HF 仓库）。
--dataset alpaca_gpt4_zh,identity 指定数据集名称，必须在 dataset_info.json 中注册。
--template llama3 极重要。指定特殊 Token 模板（如 qwen, gemma）。选错会导致模型学到错误的 EOS Token，导致生成无限重复。
--cutoff_len 4096 训练时的最大截断长度（Sequence Length）。直接影响显存占用。
--packing true / false 是否开启数据打包。将多条短样本拼接至 cutoff_len，大幅提升训练吞吐量（减少 Padding 浪费）。
--val_size 0.1 自动划分验证集的比例。
--per_device_train_batch_size 4 单张显卡上的物理 Batch Size。
--gradient_accumulation_steps 8 梯度累积步数。Global_Batch_Size=物理BatchSize×梯度累积步数×GPU数量Global\_Batch\_Size = 物理BatchSize \times 梯度累积步数 \times GPU数量Global_Batch_Size=物理BatchSize×梯度累积步数×GPU数量。
--neftune_noise_alpha 5 / 10 NEFTune 噪声系数。通过在 Embedding 层加入随机噪声，能显著提升模型在指令微调中的泛化能力和回答长度。

KV cache

Created2026-06-14|Updated2026-06-14|大模型优化
|Word Count:2.7k|Reading Time:10mins|Post Views:

Why KV cache?

大语言模型的自回归（Autoregressive）生成有一个特点：逐字（Token）输出。
每次生成下一个 Token 时，模型都需要计算当前 Token 与之前所有 Token 的注意力（Attention）关系。

没有KV cache的情况
例如，当输入 “The cat sat on” 时，模型为了预测下一个词，需要计算这 4 个词的 Q,K,VQ, K, VQ,K,V 矩阵。

举例：对于Decoder-only模型的推理场景，假设输入 “The cat sat on”，希望输出下一个词 “the”。

step1：

  • 首先计算这 4 个词的 K,VK, VK,V 矩阵
  • 计算"on"的 QQQ 矩阵（其实4个词的QQQ矩阵都被计算出来了，这是由于底层采用的是矩阵运算，但是实际使用的只有"on"的QQQ矩阵）
  • 以 "The cat sat on"的 K,VK, VK,V 矩阵为基准，计算"on"的QQQ 矩阵与 KKK 矩阵的注意力矩阵
  • 输出“the"

当前状态：“The cat sat on the”

  • 计算“The cat sat on the”的 K,VK, VK,V 矩阵
  • 计算"the"的 QQQ 矩阵（其实5个词的QQQ矩阵都被计算出来了，这是由于底层采用的是矩阵运算，但是实际使用的只有"the"的QQQ矩阵）
  • 以 "The cat sat on the"的 K,VK, VK,V 矩阵为基准，计算"the"的QQQ 矩阵与 KKK 矩阵的注意力矩阵
  • 输出“table"

可以看到，在没有KV cache的情况下，模型需要反复计算 The cat sat on 4个词的 K,VK, VK,V 矩阵，所以我们可以把这4个词的 K,VK, VK,V 矩阵缓存起来，后续的推理中直接使用缓存的 K,VK, VK,V 矩阵。

How KV cache works?

基础原理

还是以上面的例子说明：

阶段一：Prefill（首字阶段，对应你的 Step 1）

  • 输入：“The cat sat on”
  • 计算：把这 4 个词作为一个整体矩阵，一次性算出它们各自的 Q,K,VQ, K, VQ,K,V。
  • 缓存：把 [KThe,Kcat,Ksat,Kon][K_{The}, K_{cat}, K_{sat}, K_{on}][KThe​,Kcat​,Ksat​,Kon​] 和 [VThe,Vcat,Vsat,Von][V_{The}, V_{cat}, V_{sat}, V_{on}][VThe​,Vcat​,Vsat​,Von​] 存入显存（KV Cache）。
  • 注意力：用 QonQ_{on}Qon​ 与缓存中 4 个词的 KKK 计算注意力。
  • 输出：“the”。

阶段二：Decoding（增量解码阶段，对应你的 Step 2）

  • 输入：仅仅输入上一步生成的单个词 “the”。
  • 计算：模型只计算这一个词的 Qthe,Kthe,VtheQ_{the}, K_{the}, V_{the}Qthe​,Kthe​,Vthe​。(前 4 个词的任何矩阵在这一步连碰都不碰)。
  • 更新缓存：把新算出来的 Kthe,VtheK_{the}, V_{the}Kthe​,Vthe​ 追加到显存里的 KV Cache 中。此时 Cache 里变成了 5 个词的 K,VK, VK,V。
  • 注意力：用刚刚算出来的唯一一个 QtheQ_{the}Qthe​，去跟缓存中完整的 5 个词的 KKK 矩阵计算注意力。
  • 输出：“table”。

总结KV Cache 的工作流程

阶段一：Prefill（预填充 / 首字阶段）

  • 动作：用户输入一段 Prompt（假设有 NNN 个 Token）。模型一次性并行处理这 NNN 个 Token。
  • 计算：计算这 NNN 个 Token 的 Q,K,VQ, K, VQ,K,V。
  • 缓存：将这 NNN 个 Token 产生的 KKK 和 VVV 矩阵保存到显存中。
  • 输出：生成第一个预测的 Token（第 N+1N+1N+1 个 Token）。

阶段二：Decoding（解码 / 后续字阶段）

  • 动作：利用前一步生成的单 Token（第 N+1N+1N+1 个 Token）作为输入，预测下一个 Token。
  • 计算：仅计算这一个新 Token 的 QN+1,KN+1,VN+1Q_{N+1}, K_{N+1}, V_{N+1}QN+1​,KN+1​,VN+1​。
  • 拼接（Append）：将新计算的 KN+1K_{N+1}KN+1​ 和 VN+1V_{N+1}VN+1​ 追加到之前缓存的 K,VK, VK,V 矩阵后面。
  • Attention 计算：用当前的 QN+1Q_{N+1}QN+1​ 与更新后的完整 K,VK, VK,V 缓存进行注意力机制计算。
  • 循环：重复此阶段，直到模型输出结束符（EOS）或达到最大长度。

decoder中的多层KV cache细节

按照上面的逻辑，只有第一层的输入能把所有 K,VK, VK,V 矩阵缓存起来，后续的输入因为layer1的输出变了，所以无法存储，可事实是这样吗？

还是以上面的例子说明：
无KV cache：
step1：

  • layer1:
    • 首先计算这 4 个词的 Q,K,VQ,K, VQ,K,V 矩阵(大小为4×d)
    • 计算注意力矩阵
    • 输出layer1的输出(大小为4×d)
  • layer2:
    • 输入layer1的输出(大小为4×d)
    • 进入标准多头注意力机制计算，输出依然为(大小为4×d)

当前状态：“The cat sat on the”
step2：

  • layer1:
    • 计算“The cat sat on the”的 Q,K,VQ, K, VQ,K,V 矩阵(大小为5×d)
    • 输出layer1的输出(大小为5×d)
  • layer2:
    • 输入layer1的输出(大小为5×d)
    • 进入标准多头注意力机制计算，输出依然为(大小为5×d)

注意，这里step2的layer1的输出中的前4行和step1的layer1的输出中的前4行是一样的，只是第5行是新的。在后面的层中也是这个情况，所以我们可以在每一层都存储下所有的 K,VK, VK,V 矩阵，在计算时只需要计算第5行即可。

有KV cache：
step1：

  • layer1:
    • 计算"on"的 Klayer1,Vlayer1,Qlayer1K_{layer1}, V_{layer1}, Q_{layer1}Klayer1​,Vlayer1​,Qlayer1​ 矩阵(1×d)
    • 获取缓存中的前面三个token的K3layer1,V3layer1K_{3layer1}, V_{3layer1}K3layer1​,V3layer1​ 矩阵(大小为 3×d)
    • 拼接"The cat sat on"的 K,VK, VK,V 矩阵得到K4layer1,V4layer1K_{4layer1}, V_{4layer1}K4layer1​,V4layer1​，计算Qlayer1Q_{layer1}Qlayer1​ 矩阵与 K4layer1,V4layer1K_{4layer1}, V_{4layer1}K4layer1​,V4layer1​ 矩阵的注意力矩阵
    • 输出layer1的输出(大小为1×d)
    • 缓存K4layer1,V4layer1K_{4layer1}, V_{4layer1}K4layer1​,V4layer1​
  • layer2:
    • 输入layer1的输出(大小为1×d)并计算Klayer2,Vlayer2,Qlayer2K_{layer2}, V_{layer2}, Q_{layer2}Klayer2​,Vlayer2​,Qlayer2​ 矩阵(1×d)
    • 拿到之前layer2的对于前三个token的K3layer2,V3layer2K_{3layer2}, V_{3layer2}K3layer2​,V3layer2​ 矩阵(大小为 3×d)
    • 拼接K3layer2,V3layer2K_{3layer2}, V_{3layer2}K3layer2​,V3layer2​与Klayer2,Vlayer2K_{layer2}, V_{layer2}Klayer2​,Vlayer2​得到K4layer2,V4layer2K_{4layer2}, V_{4layer2}K4layer2​,V4layer2​，与Qlayer2Q_{layer2}Qlayer2​计算注意力矩阵
    • 进入标准多头注意力机制计算，输出依然为(大小为1×d)
    • 缓存K4layer2,V4layer2K_{4layer2}, V_{4layer2}K4layer2​,V4layer2​

当前状态：“The cat sat on the” （新生成了第 5 个词 “the”）
step2：

  • layer1:
    • 计算最新词 "the" 的 Klayer1,Vlayer1,Qlayer1K_{\text{layer1}}, V_{\text{layer1}}, Q_{\text{layer1}}Klayer1​,Vlayer1​,Qlayer1​ 矩阵（大小为 1×d1 \times d1×d）。
    • 获取缓存中的前面四个 token (The cat sat on) 的 K4layer1,V4layer1K_{4\text{layer1}}, V_{4\text{layer1}}K4layer1​,V4layer1​ 矩阵（大小为 4×d4 \times d4×d，这就是在 step1 结束时刚刚更新并存好的缓存）。
    • 拼接得到完整的 K5layer1,V5layer1K_{5\text{layer1}}, V_{5\text{layer1}}K5layer1​,V5layer1​（大小为 5×d5 \times d5×d），然后用当前的 Qlayer1Q_{\text{layer1}}Qlayer1​（大小为 1×d1 \times d1×d）与它们计算注意力矩阵。
    • 输出 layer1 针对当前词的输出（大小为 1×d1 \times d1×d）。
    • 将最新的 Klayer1,Vlayer1K_{\text{layer1}}, V_{\text{layer1}}Klayer1​,Vlayer1​ 追加到缓存中，此时 Layer 1 的缓存更新为 K5layer1,V5layer1K_{5\text{layer1}}, V_{5\text{layer1}}K5layer1​,V5layer1​。
  • layer2:
    • 输入来自 layer1 的输出（大小为 1×d1 \times d1×d），并计算该词在第二层的 Klayer2,Vlayer2,Qlayer2K_{\text{layer2}}, V_{\text{layer2}}, Q_{\text{layer2}}Klayer2​,Vlayer2​,Qlayer2​ 矩阵（大小为 1×d1 \times d1×d）。
    • 拿到之前 layer2 缓存的对于前四个 token 的 K4layer2,V4layer2K_{4\text{layer2}}, V_{4\text{layer2}}K4layer2​,V4layer2​ 矩阵（大小为 4×d4 \times d4×d）。
    • 拼接 K4layer2,V4layer2K_{4\text{layer2}}, V_{4\text{layer2}}K4layer2​,V4layer2​ 与最新的 Klayer2,Vlayer2K_{\text{layer2}}, V_{\text{layer2}}Klayer2​,Vlayer2​ 得到 K5layer2,V5layer2K_{5\text{layer2}}, V_{5\text{layer2}}K5layer2​,V5layer2​（大小为 5×d5 \times d5×d）。
    • 用当前的 Qlayer2Q_{\text{layer2}}Qlayer2​（大小为 1×d1 \times d1×d）与这个 5×d5 \times d5×d 的 K,VK, VK,V 矩阵计算注意力，进入多头注意力机制和后续的前馈网络（FFN）计算，最终输出依然为（大小为 1×d1 \times d1×d）。
    • 将最新的 Klayer2,Vlayer2K_{\text{layer2}}, V_{\text{layer2}}Klayer2​,Vlayer2​ 追加到缓存中，此时 Layer 2 的缓存更新为 K5layer2,V5layer2K_{5\text{layer2}}, V_{5\text{layer2}}K5layer2​,V5layer2​，供预测再下一个词时使用。

结论：模型中的每一层都需要做KV cache，才能实现高效的推理。

What does KV cache bring?

虽然 KV Cache 极大地提高了推理速度，但它将原本的计算密集型（Compute-bound）任务变成了内存带宽密集型（Memory-bound）任务，并带来了巨大的显存压力。

对于一个使用标准多头注意力机制（MHA）的模型，KV Cache 的大小（字节数）可以通过以下公式计算：

Size=2×2×nlayers×nheads×dhead×s×b\text{Size} = 2 \times 2 \times n_{\text{layers}} \times n_{\text{heads}} \times d_{\text{head}} \times s \times b Size=2×2×nlayers​×nheads​×dhead​×s×b

  • 第一个 2：代表 KKK 和 VVV 两个矩阵。
  • 第二个 2：代表 FP16 或 BF16 精度占用的字节数（2 Bytes）。
  • nlayersn_{\text{layers}}nlayers​：模型的层数（Layer count）。
  • nheadsn_{\text{heads}}nheads​：注意力头数（Head count）。
  • dheadd_{\text{head}}dhead​：每个头的维度（Head dimension）。
  • sss：序列长度（Sequence length，包括 Prompt 和生成的 Token 总和）。
  • bbb：Batch Size（批次大小）。

KV Cache 的核心优化技术

架构层面的优化（从模型设计入手）

MQA和GQA，见相关博客

显存管理层面的优化（从工程落地入手）

  • vLLM (PagedAttention)：传统的 KV Cache 需要在显存中开辟连续的空间，这会导致严重的显存碎片化，且必须为每个请求预分配最大长度的显存（造成极大浪费）。vLLM 借鉴了操作系统虚拟内存的思想，将 KV Cache 离散地存储在不连续的“内存页（Pages）”中，动态分配，将显存利用率提升至 96% 以上，吞吐量提升数倍。
  • FlashDecoding：针对长文本（Long-context）自回归解码阶段的优化。在长文本下，KV Cache 很大，单线程处理变慢。FlashDecoding 通过将 KV Cache 在序列长度维度上进行并行切片计算，最后再做 Reduce 汇聚，极大地提升了长文本下的推理速度。

量化与压缩（从数据精度入手）

  • KV Cache 量化（INT8 / INT4）：将原本 FP16/BF16 存储的 K,VK, VK,V 矩阵量化为 INT8 甚至 INT4 格式。直接将 KV Cache 的显存占用砍掉 50% ~ 75%，从而支持更大的 Batch Size。
  • Token 裁剪 / 留存（StreamingLLM 等）：在超长文本对话中，只保留最近的窗口 Token 的 KV Cache 以及最早的几个 Anchor Token（Attention Sink），抛弃中间不重要的 Token，实现无限长度的流式对话。

总结

KV Cache 是大模型工程落地（LLM Serving）的基石。
它用显存空间换取了宝贵的计算时间，使得实时聊天、高效推理成为可能。理解 KV Cache 的工作原理以及围绕它展开的工程优化（如 GQA、PagedAttention），是深入大模型工程和性能调优的核心关键。

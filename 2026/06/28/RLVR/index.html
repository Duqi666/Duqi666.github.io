强化学习与可验证奖励：RLVR

Created2026-06-28|Updated2026-06-28|强化学习
|Word Count:450|Reading Time:1mins|Post Views:

核心思想是：彻底抛弃由神经网络担任的“主观裁判”（Reward Model），改用由代码、规则或物理环境担任的“客观裁判”（Verifier）。

RLVR 的核心机制：环境与奖励的解耦

在传统的 RLHF 中，由于 Reward Model（RM）本身也是一个神经网络，它随着 Policy 的更新很容易被“欺骗”（Reward Hacking）。

而在 RLVR 规范中，奖励函数被固定为了一个不可作弊的外部验证器（External Verifier）。

验证器的类型

  • 确定性验证器（Deterministic Verifier）：
    • 数学：通过正则表达式或特定的 Parser（如 Python 的 sympy 库）提取模型输出的最后一句话（例如 \boxed{42}），直接与 Ground Truth 进行文本或数学等价性对比。得分非 0 即 1。
    • 代码：将模型生成的代码块单独提取出来，丢进一个隔离的沙盒环境（Sandbox）中，直接执行预设的若干个单元测试用例（Unit Tests）。
  • 交互式验证器（Interactive/Environment Verifier）：
    • Tool Learning / Web Browsing：模型生成一个 API 调用命令或点击操作，外部环境返回执行结果（如网页 HTML、数据库返回行数）。模型需要多步交互，最终达成目标（如“帮我成功订一张明天去北京的机票”），验证器根据最终状态是否达成来给分。

RLVR 规范的三阶段训练流

阶段一：冷启动与行为规范（SFT 阶段）

  • 算法实体：Base Model $\rightarrow$ $\pi_{\theta}^{SFT}$
  • 算法结合点：
    在这一阶段，使用标准的自回归交叉熵损失（Cross-Entropy Loss），在含有长思维链（CoT）的数据集 $\mathcal{D}_{SFT}$ 上对 Base 模型进行微调：其中，Target 序列 $y$ 的格式被严格规范为：认知前缀 + <think> 思考过程/中间试错 </think> 最终答案。
  • 阶段动力学（对 RLVR 的意义）：
    如果直接在 Base 模型上跑强化学习，由于代码沙盒或数学验证器的反馈是稀疏且极其硬性的，模型盲目采样到正确答案的概率 $P(R>0) \approx 0$，导致优化算法组内所有样本得分全为 0，优势函数（Advantage）失去方差，梯度挂零。SFT 的唯一目的，是让 $\pi_{\theta}^{SFT}$ 在阶段三的初始采样中，至少有 5%~10% 的概率踩中验证器的得分点。

阶段二：环境建立与奖励塑造（Verifier 阶段，原 Reward Model 阶段）

  • 算法实体：外部确定性验证器 $V(x, y)$（不含任何神经网络参数，由规则/代码组成）。

  • 算法结合点：
    在此阶段，需要把业务指标（如：数学必须对、代码必须过单测、格式不能崩）显式地转化为一个确定性的标量函数，作为阶段三策略迭代的真实环境奖励（Ground Truth Reward）。

    总奖励 $R_{total}$ 绝不是单一的 0 和 1，而是由优化目标和约束项构成的复合确定性奖励（Composite Reward）：

    • $R_{correct}$：硬性正确奖励。如 LeetCode 测试用例通过率（$\frac{\text{Passed}}{\text{Total}} \in [0, 1]$）或数学最终解比对。
    • $R_{format}$：格式约束项。检测生成文本中是否完整闭合了 <think> 和 </think> 标签，未闭合则强行扣分，约束模型的输出拓扑。
    • $\text{Length}(y)$：长度正规化（Length Regularization）。与 Token 长度正相关，防止模型在阶段三通过“疯狂复读”或“穷举废话”来钻验证器的空子（Reward Hacking）。

阶段三：探索、反思与策略迭代（RL阶段）

  • 算法实体：Actor 策略网络 $\pi{\theta}$（初始化自 $\pi{\theta}^{SFT}$）。根据底层算法不同，可能包含 Reference 网络 $\pi{ref}$ 或 Critic 网络 $V{\psi}$。
  • 通用数据流（从采样到验证）：
    1. 环境采样：Actor 策略 $\pi_{\theta}$ 针对输入 Prompt $x$，通过自回归采样生成推理轨迹 $y$（包含 <think> 过程与最终答案）。
    2. 外部验证：将生成结果 $y$ 送入阶段二的确定性 Verifier，立即获得无噪声的复合奖励 $R_{total}(x, y)$。

接下来，根据选择的底层优化器（Optimizer）不同，算法的更新动力学分为以下三种主流路线：

路线 A：选择 GRPO 作为优化器（组内相对寻优）

  • 架构特点：无需 Critic 网络，显存占用极低，适合大规模长文本（CoT）并行训练。
  • 算法结合点：
    $\pi_{\theta}$ 对每个 $x$ 并行采样一组输出 ${y_1, y_2, \dots, y_G}$，Verifier 给出对应的一组标量奖励。不依赖 Critic 估计 Baseline，直接进行组内归一化计算优势函数（Advantage）：利用此 $Ai$ 带入 Clip 目标函数更新 $\pi{\theta}$。
  • 动力学表现：组内正负对抗。 组内算错的样本（0分）被赋予负优势，算对或有自我纠错行为（1分）的样本被赋予正优势。梯度通过拉大组内相对剪刀差，强化“回溯、反思”的 Token 序列。

路线 B：选择 PPO 作为优化器（绝对价值寻优）

  • 架构特点：需要常驻 Actor、Ref、Critic、Reward（此处为 Verifier）四个网络。利用 Critic 逼近状态价值，样本利用率理论上更高。
  • 算法结合点：
    $\pi{\theta}$ 采样生成轨迹 $y$。由于 RLVR 的奖励 $R{total}$ 通常在最终 Token（或步骤结束时）才由 Verifier 给出，这导致了严重的稀疏奖励问题。
    此时，Critic 网络 $V_{\psi}$ 必须在中间的每一个推理 Token 或推理步骤上，去估计当前的广义优势函数（GAE）：通过 Clipped Objective 更新 Actor，同时通过 MSE Loss 迭代更新 Critic。
  • 动力学表现：绝对价值对齐。 随着 Critic 训练成熟，它能精准识别出中间思维链走到哪一步时（比如第 50 个 Token 算错了一个正负号）价值开始暴跌，从而为 Actor 提供精细到 Token/步骤级别的信用分配（Credit Assignment）。

路线 C：选择 DPO / Online DPO 作为优化器（隐式偏好寻优）

  • 架构特点：彻底扔掉显式的强化学习框架，没有 Advantage，没有 Critic，直接通过分类损失（Classification Loss）更新权重。
  • 算法结合点：
    1. 在线采样与配对（Online Pairing）：$\pi_{\theta}$ 针对 $x$ 采样两个输出 $y_1, y_2$。
    2. Verifier 贴标签：扔进验证器，如果 $R{total}(x, y_1) > R{total}(x, y_2)$，则自动将 $y_1$ 标记为赢家（$y_w$）， $y_2$ 标记为输家（$y_l$）。
    3. 模型更新：直接带入 DPO 损失函数进行显式梯度下降：
  • 动力学表现：概率似然推拉。 DPO 在算法层面不关心中间的状态转移。只要 Verifier 判定 $yw$ 是对的，算法就会直接拉高 $\pi{\theta}$ 生成 $y_w$ 的全序列对数似然（Log-likelihood），同时压低错误序列 $y_l$ 的概率。

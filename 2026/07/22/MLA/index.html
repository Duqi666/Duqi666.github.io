MLA（Multi-head Latent Attention）详细介绍

MLA（Multi-head Latent Attention）是 DeepSeek-V2/V3 中提出的核心架构创新，其本质是通过低秩压缩和解耦位置编码来大幅降低推理时的 KV Cache 开销。以下严格遵循原论文的符号体系进行介绍。

1. 核心思想：低秩压缩

标准 MHA 中，每个 token 需要缓存完整的 Key 和 Value，维度为 2nhdh2 n_h d_h2nh​dh​。MLA 的核心改动是引入一个低维的联合潜向量 ctKV\mathbf{c}_t^{KV}ctKV​ 来替代它们。

压缩过程

对于第 ttt 个 token 的输入 ht∈Rd\mathbf{h}_t \in \mathbb{R}^{d}ht​∈Rd，首先通过一个下投影矩阵将其压缩为低维潜向量：

ctKV=WDKVht(41)\mathbf{c}_t^{KV} = W^{DKV} \mathbf{h}_t \tag{41} ctKV​=WDKVht​(41)

其中，WDKV∈Rdc×dW^{DKV} \in \mathbb{R}^{d_c \times d}WDKV∈Rdc​×d，dcd_cdc​ 是 KV 压缩维度，远小于 nhdhn_h d_hnh​dh​。在推理时，我们只需要缓存这个 ctKV\mathbf{c}_t^{KV}ctKV​。

重建过程

在计算注意力时，再通过上投影矩阵将潜向量恢复为完整的 K 和 V：

ktC=WUKctKV,vtC=WUVctKV(43)\mathbf{k}_t^C = W^{UK} \mathbf{c}_t^{KV}, \quad \mathbf{v}_t^C = W^{UV} \mathbf{c}_t^{KV} \tag{43} ktC​=WUKctKV​,vtC​=WUVctKV​(43)

这里，ktC\mathbf{k}_t^CktC​ 和 vtC\mathbf{v}_t^CvtC​ 是不含位置信息的、压缩后的 Key 和 Value。

2. 处理位置编码（RoPE）的挑战

直接对压缩后的 ctKV\mathbf{c}_t^{KV}ctKV​ 应用 RoPE 会破坏其低秩特性，导致无法通过缓存潜向量来节省显存。

为此，MLA 采用了解耦 RoPE 的策略：将位置信息从主流的 KV 压缩流中分离出来。

共享的 Key 部分

额外生成一个维度较小的、携带 RoPE 的 Key 向量 ktR\mathbf{k}_t^RktR​。这个向量是跨所有注意力头共享的：

ktR=RoPE(WKRht)(44)\mathbf{k}_t^R = \text{RoPE}(W^{KR} \mathbf{h}_t) \tag{44} ktR​=RoPE(WKRht​)(44)

其中 WKR∈RdhR×dW^{KR} \in \mathbb{R}^{d_h^R \times d}WKR∈RdhR​×d，dhRd_h^RdhR​ 是解耦后的 RoPE 维度。

Query 的处理

相应地，每个注意力头的 Query 也被拆分为内容部分和位置部分：

qt,i=[qt,iC;qt,iR](40)\mathbf{q}_{t,i} = [\mathbf{q}_{t,i}^C; \mathbf{q}_{t,i}^R] \tag{40} qt,i​=[qt,iC​;qt,iR​](40)

  • qt,iC\mathbf{q}_{t,i}^Cqt,iC​ 来自对压缩向量的上投影（不含位置信息）
  • qt,iR\mathbf{q}_{t,i}^Rqt,iR​ 来自另一条路径，并应用了 RoPE

3. 完整计算流程与缓存

对于第 iii 个注意力头，完整的计算流程如下：

Query 生成

ctQ=WDQht(37)\mathbf{c}_t^Q = W^{DQ} \mathbf{h}_t \tag{37} ctQ​=WDQht​(37)

[qt,1C;qt,2C;… ;qt,nhC]=WUQctQ(38)[\mathbf{q}_{t,1}^C; \mathbf{q}_{t,2}^C; \dots; \mathbf{q}_{t,n_h}^C] = W^{UQ} \mathbf{c}_t^Q \tag{38} [qt,1C​;qt,2C​;…;qt,nh​C​]=WUQctQ​(38)

qt,iR=RoPE(WQRctQ)(39)\mathbf{q}_{t,i}^R = \text{RoPE}(W^{QR} \mathbf{c}_t^Q) \tag{39} qt,iR​=RoPE(WQRctQ​)(39)

qt,i=[qt,iC;qt,iR]\mathbf{q}_{t,i} = [\mathbf{q}_{t,i}^C; \mathbf{q}_{t,i}^R] qt,i​=[qt,iC​;qt,iR​]

KV 生成与缓存

ctKV=WDKVht(缓存此向量及 ktR)\mathbf{c}_t^{KV} = W^{DKV} \mathbf{h}_t \quad \text{(缓存此向量及 } \mathbf{k}_t^R\text{)} ctKV​=WDKVht​(缓存此向量及 ktR​)

kt,iC=WUKctKV(实际推理时通过矩阵吸收优化，无需显式计算)\mathbf{k}_{t,i}^C = W^{UK} \mathbf{c}_t^{KV} \quad \text{(实际推理时通过矩阵吸收优化，无需显式计算)} kt,iC​=WUKctKV​(实际推理时通过矩阵吸收优化，无需显式计算)

vt,iC=WUVctKV\mathbf{v}_{t,i}^C = W^{UV} \mathbf{c}_t^{KV} vt,iC​=WUVctKV​

注意力计算

最终的注意力分数由两部分点积相加得到：

Score=qt,iC⋅kj,iC+qt,iR⋅kjR\text{Score} = \mathbf{q}_{t,i}^C \cdot \mathbf{k}_{j,i}^C + \mathbf{q}_{t,i}^R \cdot \mathbf{k}_{j}^R Score=qt,iC​⋅kj,iC​+qt,iR​⋅kjR​

其中，第一部分是内容间的交互，第二部分是位置间的交互。

4. 效率对比

下表清晰展示了不同注意力机制的 KV Cache 大小对比。可以看到，MLA 将每个 token 的缓存从 2nhdh2 n_h d_h2nh​dh​ 压缩到了 dc+dhRd_c + d_h^Rdc​+dhR​，在 DeepSeek-V2 的配置下，相当于只用了约 2.25 组 GQA 的缓存开销，却能保持与 MHA 相当的性能。

方法 每 Token KV Cache 大小（元素个数）
MHA 2nhdh2 n_h d_h2nh​dh​
GQA 2Gdh2 G d_h2Gdh​（G 为组数）
MLA dc+dhR\mathbf{d_c + d_h^R}dc​+dhR​

在 DeepSeek-V2 中，dc=512d_c = 512dc​=512，dhR=128d_h^R = 128dhR​=128，与标准 MHA 相比，KV Cache 可以压缩至原来的约 1/161/161/16。

吸收优化（Absorption Optimization）详细介绍

吸收优化是 MLA 工程落地的关键一步。如果不做这个优化，虽然 KV Cache 变小了，但推理时的计算量会不减反增，因为我们需要实时将低维的 ctKV\mathbf{c}_t^{KV}ctKV​ 解码成高维的完整 K 和 V 来计算注意力。

吸收优化的核心数学原理是矩阵乘法的结合律，即通过调整计算顺序，将"解码"过程（上投影矩阵 WUKW^{UK}WUK 和 WUVW^{UV}WUV）吸收进 QQQ 的投影矩阵（WUQW^{UQ}WUQ）或最终的输出投影矩阵（WOW^OWO）中。

以下是具体的推导和机制，严格遵循原论文符号。

1. 为什么需要吸收优化？

在没有优化的情况下，对于第 ttt 个 Query token 和第 jjj 个 Key token，Q 和 K 的内容部分计算如下：

  • Query 内容：qt,iC=WiUQctQ\mathbf{q}_{t,i}^C = W^{UQ}_i \mathbf{c}_t^Qqt,iC​=WiUQ​ctQ​（这里的 WiUQW^{UQ}_iWiUQ​ 是从总矩阵 WUQW^{UQ}WUQ 中按头切分的部分）
  • Key 内容：kj,iC=WiUKcjKV\mathbf{k}_{j,i}^C = W^{UK}_i \mathbf{c}_j^{KV}kj,iC​=WiUK​cjKV​

那么，计算内容部分的注意力分数（点积）就是：

(qt,iC)⊤kj,iC=(WiUQctQ)⊤(WiUKcjKV)(\mathbf{q}_{t,i}^C)^\top \mathbf{k}_{j,i}^C = (W^{UQ}_i \mathbf{c}_t^Q)^\top (W^{UK}_i \mathbf{c}_j^{KV}) (qt,iC​)⊤kj,iC​=(WiUQ​ctQ​)⊤(WiUK​cjKV​)

展开后得到：

(ctQ)⊤(WiUQ)⊤WiUKcjKV(\mathbf{c}_t^Q)^\top (W^{UQ}_i)^\top W^{UK}_i \mathbf{c}_j^{KV} (ctQ​)⊤(WiUQ​)⊤WiUK​cjKV​

关键观察：在推理过程中，ctQ\mathbf{c}_t^QctQ​ 和 cjKV\mathbf{c}_j^{KV}cjKV​ 是维度很低的向量（例如 512 维），而 WiUQW^{UQ}_iWiUQ​（维度 dh×dcd_h \times d_cdh​×dc​）和 WiUKW^{UK}_iWiUK​（维度 dh×dcd_h \times d_cdh​×dc​）是很大的矩阵（维度例如 128×512）。

如果先计算高维的 q\mathbf{q}q 和 k\mathbf{k}k，不仅计算量大，而且会产生巨大的中间张量显存占用。我们需要消除这些高维矩阵运算。

2. 针对 Key 的吸收优化（吸收进 Q）

我们注意到，中间的高维矩阵 (WiUQ)⊤WiUK(W^{UQ}_i)^\top W^{UK}_i(WiUQ​)⊤WiUK​ 实际上是一个低维空间中的方阵（维度 dc×dcd_c \times d_cdc​×dc​）。

在数学推导层面，我们可以直接将中间这个矩阵定义为新的投影矩阵：

Winew=(WiUQ)⊤WiUK\boxed{W^{new}_i = (W^{UQ}_i)^\top W^{UK}_i} Winew​=(WiUQ​)⊤WiUK​​

这个 WinewW^{new}_iWinew​ 的维度是 dc×dcd_c \times d_cdc​×dc​。

此时，注意力分数的计算变成了：

Scorecontent=(ctQ)⊤WinewcjKV\text{Score}_{content} = (\mathbf{c}_t^Q)^\top W^{new}_i \mathbf{c}_j^{KV} Scorecontent​=(ctQ​)⊤Winew​cjKV​

这样，整个过程就完全在低维空间 dcd_cdc​ 中进行了。

工程实现视角

在实际的推理内核（CUDA Kernel）实现中，为了保持计算流水线的统一性，工程师们通常不会显式地创建一个新的 WinewW^{new}_iWinew​ 矩阵，而是修改权重加载的逻辑：

  1. 不改变 Q 的生成方式：依然用 WUQW^{UQ}WUQ 去生成当前 token 的 Query（即 qt,iC=WiUQctQ\mathbf{q}_{t,i}^C = W^{UQ}_i \mathbf{c}_t^Qqt,iC​=WiUQ​ctQ​）

  2. 在计算 Attention 之前，对 Query 做一次"吸收变换"：
    将生成的 qt,iC\mathbf{q}_{t,i}^Cqt,iC​（高维 dhd_hdh​）左乘上一个融合矩阵，将其投影回低维空间 dcd_cdc​：

    q~t,iC=WiUQ⋅(WiUK)⊤⋅qt,iC\tilde{\mathbf{q}}_{t,i}^C = W^{UQ}_i \cdot (W^{UK}_i)^\top \cdot \mathbf{q}_{t,i}^C q~​t,iC​=WiUQ​⋅(WiUK​)⊤⋅qt,iC​

    这个 q~t,iC\tilde{\mathbf{q}}_{t,i}^Cq~​t,iC​ 的维度是 dcd_cdc​。

这种做法在数学上与直接计算 WinewctQW^{new}_i \mathbf{c}_t^QWinew​ctQ​ 完全等价，但在工程上允许复用原有的 Q 投影算子。

标准描述（基于原论文）

原论文在描述吸收优化时，更偏向于"直接相乘"的视角：

我们不计算完整的 kt,iC\mathbf{k}_{t,i}^Ckt,iC​ 和 qt,iC\mathbf{q}_{t,i}^Cqt,iC​ 的高维点积。而是通过将 WUKW^{UK}WUK 吸收进 WUQW^{UQ}WUQ，等效地将 (WUQ)⊤WUK(W^{UQ})^\top W^{UK}(WUQ)⊤WUK 作为一个整体的低维映射矩阵，直接作用于 ctQ\mathbf{c}_t^QctQ​ 和 cjKV\mathbf{c}_j^{KV}cjKV​。

严谨的写法是：

Scorecontent=(ctQ)⊤((WiUQ)⊤WiUK)⏟吸收后的低维计算cjKV\text{Score}_{content} = \underbrace{(\mathbf{c}_t^Q)^\top \left( (W^{UQ}_i)^\top W^{UK}_i \right)}_{\text{吸收后的低维计算}} \mathbf{c}_j^{KV} Scorecontent​=吸收后的低维计算(ctQ​)⊤((WiUQ​)⊤WiUK​)​​cjKV​

3. 针对 Value 的吸收优化（吸收进 O）

对于 Value 部分，计算注意力输出 ot,i\mathbf{o}_{t,i}ot,i​ 时，需要将注意力权重 α\alphaα 乘以高维的 vj,iC\mathbf{v}_{j,i}^Cvj,iC​：

ot,i=∑jαt,j⋅vj,iC=∑jαt,j⋅(WiUVcjKV)\mathbf{o}_{t,i} = \sum_{j} \alpha_{t,j} \cdot \mathbf{v}_{j,i}^C = \sum_{j} \alpha_{t,j} \cdot (W^{UV}_i \mathbf{c}_j^{KV}) ot,i​=j∑​αt,j​⋅vj,iC​=j∑​αt,j​⋅(WiUV​cjKV​)

直接计算会产生高维的中间结果。我们将 WiUVW^{UV}_iWiUV​ 吸收进输出投影矩阵 WOW^OWO 中。

原本的最终输出是 ut=∑iWiOot,i\mathbf{u}_t = \sum_i W^O_i \mathbf{o}_{t,i}ut​=∑i​WiO​ot,i​。将 ot,i\mathbf{o}_{t,i}ot,i​ 的表达式代入：

ut=∑iWiO(∑jαt,jWiUVcjKV)\mathbf{u}_t = \sum_i W^O_i \left( \sum_{j} \alpha_{t,j} W^{UV}_i \mathbf{c}_j^{KV} \right) ut​=i∑​WiO​(j∑​αt,j​WiUV​cjKV​)

交换求和顺序，我们定义一个新的吸收后的输出矩阵 W~O\tilde{W}^OW~O：

W~O=∑i(WiO⋅WiUV)\tilde{W}^O = \sum_i \left( W^O_i \cdot W^{UV}_i \right) W~O=i∑​(WiO​⋅WiUV​)

优化后的效果

我们可以先计算注意力权重和低维 cjKV\mathbf{c}_j^{KV}cjKV​ 的加权和（这依然在低维空间 dcd_cdc​ 中），最后只做一次到原始维度 ddd 的投影：

ut=W~O(∑jαt,jcjKV)\mathbf{u}_t = \tilde{W}^O \left( \sum_{j} \alpha_{t,j} \mathbf{c}_j^{KV} \right) ut​=W~O(j∑​αt,j​cjKV​)

4. 最终记忆要点：Decode 阶段的极致轻量

经过吸收优化后，MLA 在自回归解码（Decode）阶段的计算流程变得极其简单：

步骤 操作
缓存 只缓存低维的 ctKV\mathbf{c}_t^{KV}ctKV​（维度 dcd_cdc​）和带 RoPE 的低维 ktR\mathbf{k}_t^RktR​（维度 dhRd_h^RdhR​）
Q 计算 使用优化后的 W~UQ\tilde{W}^{UQ}W~UQ 将当前 token 的 ctQ\mathbf{c}_t^QctQ​ 映射到低维空间
注意力分数 内容部分直接使用低维的 Q（优化后）与缓存的低维 cjKV\mathbf{c}_j^{KV}cjKV​ 做点积；位置部分使用低维的 qt,iR\mathbf{q}_{t,i}^Rqt,iR​ 与缓存的 kjR\mathbf{k}_j^RkjR​ 做点积
输出 对低维的 cjKV\mathbf{c}_j^{KV}cjKV​ 进行加权求和，最后通过吸收后的 W~O\tilde{W}^OW~O 一步映射回高维

总结：吸收优化让 MLA 在推理时，Q、K、V 的核心运算全部在压缩后的低维空间（dc≈512d_c \approx 512dc​≈512）完成，仅在最后输出时做一次高维映射。这使得 MLA 既享受了 KV Cache 的小容量，又拥有了极快的计算速度。这项优化也是 DeepSeek 能在推理成本上做到极低的重要工程基石。

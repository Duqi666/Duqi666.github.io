数据清洗

一、启发式规则过滤

利用基本规则的统计特征，快速剔除垃圾数据

  • 长度过滤：文本长度过长或过短
  • 符号密度过滤：文本中包含过多符号、emoji或HTML符号
  • 重复行去重：利用简单哈希去除完全重复的文本
  • 语言过滤：去除非目标语言文本

二、质量评估过滤

2.1 困惑度（PPL）过滤—-重点

利用模型的困惑度（PPL）来评估文本的质量，过滤掉低质量的文本。

困惑度公式：

直觉理解
模型给这段文本中每个Token分配的预测概率越高，log p 越接近0，PPL值就越低。
打分逻辑
PPL越低，代表模型对该文本的“拟合度”越高。

  • PPL很低：说明模型已经见过类似表达，文本通顺且符合语法（例如：“量子力学的波函数坍缩”）。
  • PPL极高（比如几百上千）：说明这段文本用词生僻、逻辑跳跃，甚至包含大量拼写错误。

PPL的三大先天缺陷（数学本质上的“盲区”）

缺陷1：分布偏好（Distribution Bias）—— 爱“平庸”，恨“创新”

  • 表现：PPL天然偏好高概率、低信息熵的文本。像“好的，我明白了。”这种万能废话，PPL极低；而像“通过黎曼曲面上的共形映射来解析复变函数边界问题”这种专业表达，PPL往往很高。
  • 后果：如果只保留低PPL数据，模型会变成“好好先生”，回答永远安全、平滑，但丧失深度推理和专业能力。

缺陷2：长度敏感性（Length Bias）—— 越长越吃亏

  • 表现：PPL是每个Token损失的平均值。长文本中只要出现一个极低概率的生僻词，整个平均PPL就会被剧烈拉高；而短文本即使全是废话，PPL也可能很好看。
  • 后果：长且高质量的推理链（CoT）会被误判为低质量数据而被过滤。

缺陷3：模型特异（Model Specificity）—— 换模型，分不同

  • 表现：用Llama-3算的PPL，和用Qwen-2算的PPL，绝对数值完全不可比。Llama-3训练语料偏英语网页，算中文文本的PPL天然就高；而Qwen-2算中文的PPL会低很多。
  • 后果：无法建立跨模型的统一PPL阈值，每次换基座都要重新标定，工程成本高。

工业界“进阶变种”

变种1：相对困惑度（Relative PPL）—— 解决“模型特异”

  • 做法：对每条待测数据 $ d $，计算其在基座模型上的PPL，同时计算该模型在一组通用基准语料（如C4验证集或维基百科）上的平均PPL $ PPL_{base} $，然后用比值作为分数：
  • 优点：
    • 对于不同模型的打分有了比较依据
    • 对于不同类型的文本也可以通过这种方法相互比较，例如对于数学语料，就找到数学的基准语料计算平均PPL，而日常日常对话则用日常对话的基准语料。

变种2：分位数截断 + 分段采样（Quantile Truncation）—— 解决“分布偏好”

  • 做法：不设固定的PPL阈值（如“PPL<20就保留”），而是对所有数据的PPL按升序排序，分成10个分位段（Decile）。然后从每个分位段中按比例采样，比如低分位（简单）采10%，中分位（适中）采40%，高分位（困难）采50%。
  • 优点：显式保留了“困难样本”，让模型在训练时能看到高PPL的复杂表达，从而提升推理上限。

变种3：指令-答案分离动态加权（Dynamic Weighting）—— 解决“任务错配”

  • 做法：在SFT数据中，分别计算Instruction的PPL和Answer的PPL。如果Instruction PPL很高（说明指令本身生僻），而Answer PPL很低（答案流畅），这条数据可能是“高难度指令的优质回答”，应给予更高的采样权重；反之，如果Instruction很低但Answer很高，说明指令简单但回答胡言乱语，直接丢弃。
  • 优点：把“问题难度”和“答案质量”解耦，能精准筛选出“带着脚镣跳好舞”的高质量数据。

变种4：分长度区间标准化——解决“长度敏感性”

  • 做法：把所有待测数据按长度（Token数）分桶，比如：
    • 桶1：0 ~ 50 Token
    • 桶2：51 ~ 200 Token
    • 桶3：201 ~ 500 Token
    • 桶4：500+ Token

然后在每个桶内部，分别计算均值和标准差，做Z-Score标准化。

  • 效果：一条500 Token的数学题PPL=80，它所在的“长文本桶”里平均PPL就是75，算出来Z-Score可能只有0.2，说明它在本长度区间里很正常；而一条10 Token的废话PPL=15，短文本桶里平均只有5，Z-Score高达2.0，反而被识别为异常。

第三层：致命陷阱——面试官最想听的“灾难场景”

让PPL完全失效的极端场景

陷阱1：数据污染（Contamination）—— PPL极低的“毒药”

  • 场景：如果你的待清洗数据里混入了GSM8K或MMLU的测试集，基座模型在预训练时已经见过这些题（哪怕只是相似表述），算出的PPL会异常低（比如只有2.0）。
  • 后果：模型在训练时提前“看到”了测试集答案，导致评测分数虚高，上线后效果崩塌。
  • 解法：这不是PPL能解决的问题，必须建立N-gram重叠检测（如13-gram完全匹配）和Embedding相似度阈值（如余弦相似度>0.95则标记为污染）的黑名单库。

陷阱2：对抗性样本（Adversarial Examples）—— PPL极低的“废话连篇”

  • 场景：恶意构造一段“虽然XX，但是YY”的循环废话，比如“我不确定，但也许可能大概或许……”这种文本极其流畅，PPL低至3.0。
  • 后果：模型学会输出“软绵绵”的回避式回答，失去决策力和确定感。
  • 解法：引入熵（Entropy）指标——计算模型对每个Token预测概率分布的熵。如果PPL低但熵也极低，说明文本单一刻板，需要降权。

2.2 基于分类器的质量过滤（Classifier-based Filtering）

启发式规则只能过滤掉极端的低质量数据，而 PPL 主要衡量的是语言的流利度。为了剔除“流利但无营养/低价值”的内容（如营销号、垃圾网页、无意义的对话），通常会训练高质量的文本分类器。

  • 1. 预训练数据分类器（如 FastText / 神经网络分类器）
    • 原理：收集高质量数据集（如 Wikipedia、Books、精选学术论文等）作为正样本，收集低质数据集（如 Common Crawl 的随机抓取内容）作为负样本，训练一个文本分类器。
    • 应用：给每条抓取的网页打分，设定阈值过滤掉低分文本。
  • 2. 领域/主题分类器
    • 原理：根据模型的目标定位，训练分类器筛选出特定领域（如代码、数学、科学文献）的数据，或者剔除色情、暴力、仇恨言论等有害内容。
  • 3. GPT-4 蒸馏/打分（LLM-as-a-Judge）
    • 近年来流行用强大的模型（如 GPT-4）对候选数据进行打分或重写，或者训练小模型去拟合大模型的打分标准（如 LLaMA-Clean 等工作）。

三、去重（Deduplication）—— 核心环节

大模型对重复数据极其敏感。重复数据会导致模型过拟合、降低多样性，甚至在预训练时引发记忆效应。去重通常分为三个粒度：

  • 1. 完全去重（Exact Deduplication）
    • 利用基础哈希算法（如 MD5、SHA-256）对整篇文档或段落计算哈希值，精准剔除一字不差的重复文档。
  • 2. 句子/段落级去重
    • 剔除文档内部或跨文档的大面积雷同段落（常见于网站的统一导航栏、页脚版权声明等）。
  • 3. 模糊去重（Fuzzy Deduplication）—— 重点
    • 背景：网络上存在大量“洗稿”或微调的重复内容（字面不完全一样，但语义/内容高度重合）。
    • 主流技术：
      • MinHash + LSH (Locality-Sensitive Hashing)：先利用 MinHash 将文本转化为签名，再利用 LSH 高效分桶捞出候选文档，最后在桶内通过杰卡德相似度进行精确校验与剪裁。

MinHash + LSH法：

  • Shingling (N-gram)：将文本分为N-grams，输出v_size×doc_num的矩阵（one-hot矩阵）
  • MinHash：计算N-grams的MinHash值（对每一列随机打乱，第一个出现1的行作为MinHash值，重复n次）
  • LSH：对每个文档的minihash进行切割，然后使用hash的方法对比每个文章的每一段hash，只有存在任意一段hash相同，则认为这两个文档是同一个桶中的文本

四、 隐私与敏感信息脱敏（Privacy & PII Removal）

为了符合法律法规（如 GDPR）并保护个人隐私，必须在数据清洗阶段移除敏感的个人身份信息（PII, Personally Identifiable Information）。

  • 识别与替换：
    • 利用正则表达式（Regex）或专用的 NER（命名实体识别）模型，检测并替换/抹去文本中的：
      • 手机号码、电子邮箱、身份证号、银行卡号。
      • 具体的人名、详细住址、IP 地址等。
  • API 密钥与密码过滤：
    • 针对代码和技术文档，过滤掉硬编码的 API 密钥、私钥（如 SSH Key、GitHub Token）和密码。

数据合成（Data Synthesis）

一、 指令生成（Instruction Generation）

最开始我们只会拿到一些文本，而没有“问题-回答”对数据

1.1 Evol-Instruct（进化指令 —— 《WizardLM》核心）

  • 核心逻辑：模仿人类老师出题的思路，把简单的问题一步步改造成高难度、复杂逻辑的题目。
  • 两大演化方向：
    • 深度演化（Deepening）：增加约束条件、加深推理步骤、提高任务复杂度、引入模糊或对抗性条件。
    • 广度演化（Broadening）：改变主题、领域或任务类型，实现数据的多样化（例如把“写一首关于春天的诗”演化为“写一首关于量子力学的十四行诗”）。
  • 实施方式：让强大的模型（如 GPT-4）扮演“出题人”，按照演化 Prompt 不断对种子指令进行多轮迭代升级，淘汰掉无法解析或生成的死局，保留有效的高难度指令。

2. Self-Instruct（自举指令生成）

  • 核心逻辑：由王树森老师、苏剑林等推崇的自动化方案（源自斯坦福 Self-Instruct 论文）。
  • 实施步骤：
    1. 准备极少量的种子任务（例如 175 个人工编写的指令）。
    2. 让大模型随机参考几个种子，自主“凭空想象”生成新的指令。
    3. 质量过滤：利用启发式规则和模型自身能力，剔除与已有指令重复度过高、语法错误、或无法回答的低质量指令。
    4. 将新生成的优质指令加入种子池，循环迭代，像滚雪球一样扩充指令集。

二、 答案生成与增强（Response Generation）

有了指令后，需要为其生成高质量的“标准答案”。业界早已不满足于单次生成，而是采用组合拳来拔高答案质量：

1. 多模型投票与 Best-of-N 采样

  • 多样性采样：对同一条指令，使用不同的温度参数（$Temperature > 0.7$）让模型生成多个不同的回答，或者调用多个不同的基座模型（如 GPT-4、Claude-3.5、Llama-3）同时作答。
  • Best-of-N 选优：生成 $N$ 个候选答案后，利用一个经过训练的奖励模型（Reward Model）或更强的裁判模型（LLM-as-a-Judge）对这 $N$ 个答案进行评分打分，挑选出分数最高的那一个作为最终答案。

2. Chain-of-Thought（CoT）思维链合成

  • 针对复杂推理题（如数学、代码、逻辑推理）：仅仅给出一个最终答案是不够的，模型需要学会“思考过程”。
  • 实施方式：在 Prompt 中显式引导模型逐步推理（例如：“Let’s think step by step”），并要求其输出带结构化标签的推理步骤（如 <step> 第一步... </step> <step> 第二步... </step>），这能大幅提升模型在复杂任务上的表现。

三、 偏好数据（Preference Data）合成

大模型不仅要学会正确回答，还要懂得人类的偏好（如更礼貌、更安全、更简洁）。目前主流的对齐算法（如 DPO、RLHF）极度依赖 Chosen（优选）/ Rejected（劣选） 形式的偏好对。

1. RLAIF（AI 反馈强化学习）

  • 背景：传统 RLHF 需要大量人类标注员对答案排序，成本高且周期长。
  • 做法：用最强大的模型（如 GPT-4）作为裁判，让它同时审阅对同一个问题的两个不同回答，并给出倾向性判断（指出哪个回答更好，并说明理由），从而自动化构建大规模偏好数据集。

2. 负面构造（Negative Construction）

  • 主动制造“反面教材”：为了让模型学会避坑，我们会刻意引导模型或通过技术手段生成劣质回复（Rejected 样本），常见手段包括：
    • 幻觉注入：让模型加入虚假的事实。
    • 超长/啰嗦：故意让回答包含大量车轱辘话。
    • 逻辑谬误：在推理中加入错误的中间步骤。
    • 将这些作为 Rejected，与正确的 Chosen 组成训练对，训练出的模型逻辑会更加严密。

四、 数据回译（Back-translation）

  • 跨语言能力扩充：由于互联网上高质量的中文语料相对英文较少，大厂常利用数据回译技术。
  • 流程：将海量高质量的英文网页、科学文献或代码注释，通过机器翻译（或大模型翻译）高质量地转化为中文，再结合回译校验（中文再翻译回英文比对语义损耗），从而低成本扩充多语言大模型的训练语料库。

💡 工业界合成数据流水线总结

现代大模型的数据合成已经形成了一套“生产 $\rightarrow$ 过滤 $\rightarrow$ 增强 $\rightarrow$ 对齐”的工业化闭环：

  1. 种子驱动：少量高质量人工种子 + 进化/自举算法（Evol/Self-Instruct）。
  2. 多源并发：多模型、多温度采样生成候选。
  3. AI 裁判过滤：用强模型打分、去噪、过滤低质量和有害内容。
  4. 对齐打包：构建包含 CoT 推理和 Chosen/Rejected 偏好的最终训练集。
